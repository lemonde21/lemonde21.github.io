I build software that works close to the operating system. My current project, MicSelect, hooks into iOS's audio stack so you decide which microphone your apps record from: the iPad's own mic or your earphones.

Notice: plugging in wired earphones no longer takes over your microphone on devices running MicSelect.

Developed and tested on an iPad mini 4 running iOS 15.8.6 (Dopamine).

// If the app (or WebRTC inside Discord) picks an input itself, override it.
- (BOOL)setPreferredInput:(AVAudioSessionPortDescription *)inPort error:(NSError **)outError {
    if (!sApplying) {
        AVAudioSessionPortDescription *forced = MSDesiredInput(self);
        if (forced) inPort = forced;
    }
    return %orig(inPort, outError);
}

- (BOOL)setActive:(BOOL)active withOptions:(AVAudioSessionSetActiveOptions)options error:(NSError **)outError {
    BOOL ok = %orig;
    if (ok && active) MSApply(self);
    return ok;
}

            [gLevelCell setLevel:level];

MicSelect / Overview ×

Choose which microphone your apps use.

Plug wired earphones into an iPad and iOS moves every app to the earphone mic. MicSelect keeps the iPad's built-in microphone (or forces the headset mic) in Discord and any other app that records audio, while sound still plays through your earphones.

  1. 1

    Hook

    Injected into every UIKit app, it hooks AVAudioSession and applies your choice with setPreferredInput: whenever a session activates or the audio route changes.

  2. 2

    Share

    The mode lives in notifyd state, which sandboxed apps can read, so you can switch microphones mid-call with no restart.

  3. 3

    Persist

    SpringBoard saves the choice to preferences and restores it at boot, so it survives resprings and reboots.
